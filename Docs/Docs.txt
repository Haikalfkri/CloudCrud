# CloudCRUD
## End-to-End Backend Development & DevOps Project

**Project Type:** Backend Engineering + DevOps  
**Backend:** Python + Django + Django REST Framework  
**Database:** PostgreSQL  
**Cache:** Redis  
**Application Server:** Gunicorn  
**Reverse Proxy:** Nginx  
**Containerization:** Docker & Docker Compose  
**CI/CD:** GitHub Actions  
**Container Registry:** Google Artifact Registry  
**Orchestration:** Kubernetes  
**Package Manager:** Helm  
**Infrastructure as Code:** Terraform  
**Cloud Provider:** Google Cloud Platform (GCP)  
**Monitoring:** Prometheus + Grafana  
**Observability:** OpenTelemetry  

---

# 1. Project Overview

CloudCRUD is a learning-oriented project designed to practice the complete lifecycle of a backend application, from initial development to production deployment.

The application will be a simple Product Management REST API built using Django REST Framework.

The main learning objective is not building a complex application, but understanding how backend applications are developed, containerized, automated, deployed, monitored, secured, and maintained.

## Main Objectives

- Build a RESTful API using Django REST Framework.
- Integrate PostgreSQL as the primary database.
- Implement Redis caching.
- Use Gunicorn as the production WSGI application server.
- Configure Nginx as a reverse proxy.
- Containerize the application using Docker.
- Orchestrate local services using Docker Compose.
- Automate testing and builds using GitHub Actions.
- Deploy the application using Kubernetes.
- Manage Kubernetes applications using Helm.
- Provision infrastructure using Terraform.
- Deploy the application to Google Cloud Platform.
- Implement automated CI/CD pipelines.
- Monitor application and infrastructure health.

# 2. Application Scope

Keep the application simple. Focus on infrastructure and deployment rather than adding unnecessary business features.

## Product Management API

### Product Entity

| Field | Type |
|---|---|
| id | UUID |
| name | String |
| description | Text |
| price | Decimal |
| stock | Integer |
| created_at | DateTime |
| updated_at | DateTime |

### API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | /api/products/ | Get all products |
| GET | /api/products/{id}/ | Get product by ID |
| POST | /api/products/ | Create product |
| PUT | /api/products/{id}/ | Update product |
| DELETE | /api/products/{id}/ | Delete product |

Additional endpoints:

- GET /health/
- GET /health/ready/
- GET /health/live/

- Environment-based settings.
- PostgreSQL integration.
- Database migrations.
- Global exception handling where appropriate.
- Structured logging.

- API documentation using drf-spectacular or an equivalent OpenAPI tool.

# 3. Learning Methodology

Every phase MUST follow this workflow.

## STEP 1 — LEARN FIRST

Before implementing a technology, watch tutorials and understand its fundamentals.

Activities:
- Watch relevant tutorials.
- Read official documentation.
- Understand the architecture and purpose.
- Learn important commands.
- Understand configuration files.
- Take notes.

## STEP 2 — IMPLEMENT

After learning, implement the technology independently in CloudCRUD.

Activities:
- Configure the technology.
- Integrate it with the existing project.
- Test the implementation.
- Troubleshoot errors.
- Document what you learned.

## STEP 3 — VERIFY

Before moving to the next phase:

- Make sure everything works.
- Understand the configuration.
- Be able to explain why the technology is used.
- Commit the changes to GitHub.

**Important:** Don't simply copy commands from tutorials. Try to understand and reproduce the implementation yourself.
